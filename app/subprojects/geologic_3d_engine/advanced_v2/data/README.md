# 地域岩相の読み込みデータ

GUI の地図二点指定からの生成にも自動適用します。利用者によるバッチ実行は不要です。

## データの役割

- `japan_lithology_vocabulary.json`: 日本で使用する主要29岩相の名称・照合語・対応地質区・出典と、既存岩体への適用規則。これは全国の岩相分布表ではありません。
- 各生成フォルダの `plan/regional_lithology_input.json`: その測線で取得した GSJ 地質図の原文、位置、版、出典、全候補、候補間の関係、適用範囲を保存した地域入力。
- 実データ例はプロジェクト側の `validation/regional_lithology_data_20260921/` の再生成記録と、その記録が指す生成フォルダに保存します。取得済みの府中町の約394 m測線であり、広島県全体の代表値ではありません。現在のサービスを再照会した結果とも区別します。

生成経路は「地図資料取得 → 地域入力JSON保存 → ディスクから読み込み直し → 原資料・測線・語彙版との照合 → 岩相選択 → 共有境界から幾何生成」です。読み込み用JSONは model.json と実行マニフェストへハッシュで結び付けます。

## 選択の契約

1. 地名や地形だけから岩種を決めません。資料の岩相欄を照合します。
2. 少数の地点に出現した岩相も保持します。最多の1種類だけに切り詰めません。
3. 地質図の「花崗岩・花崗閃緑岩」等は構成岩種の集合です。上下に重なる地層や個々の岩体の位置を示すとは解釈しません。
4. 互換性のある複数岩種は既存岩体の複合岩相として反映します。風化・割れ目・新鮮部の区別は保持します。岩種間の内部境界は未解決と記録します。
5. 異なる地質区の岩種など配置できない候補は削除せず `regionalLithologySelection.findings` に保留理由を記録します。構成要素のみの候補を、描画済みの独立岩体と数えません。
6. 地表地質は地下の観測ではありません。地下の深度・境界は `SyntheticAssumption` のままです。観測がない岩石を深さ・硬度だけから追加しません。

## 拡張と制限

名称や対象ユニットの追加は語彙JSONを更新し、版を上げ、出典と試験を追加します。候補一覧だけを手編集した地域入力は原資料との再構成照合で拒否されます。追加の地域資料を採用する場合は、出典付きの元資料側を更新して地域入力を再作成してください。

語彙照合は網羅的な自然言語解釈ではありません。未照合の原文も失わず保存します。地質図の集成区分を、各岩種がその地点で個別に確認された証拠へ格上げしません。全国の全地点・全岩種を収集済みとは主張しません。

出典: GSJ シームレス地質図 V2 API と CGI/GeoSciML の採用済み用語資料（語彙JSON内の出典一覧）。今回の変更は読み込み・選択経路の変更であり、地質図の分解能や地下深度の証拠を増やすものではありません。
